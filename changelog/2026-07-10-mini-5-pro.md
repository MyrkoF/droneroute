## Summary

Add DJI Mini 5 Pro support and make the Mini series export a DJI Fly-compatible
KMZ. The Mini drones now use the consumer WPML dialect (www.uav.com namespace,
files under `wpmz/`, no `payloadInfo`), so exported missions import directly into
the DJI Fly app. Resolves the long-standing note that the Mini 4 Pro's output may
not import into DJI Fly.

## Changes

- Added **DJI Mini 5 Pro** (`droneEnumValue` 68, verified from a native DJI RC2
  mission dump) to the drone model list.
- Introduced an explicit `dialect` (`"enterprise" | "consumer"`) on `DroneModel`
  and `MissionConfig`. The enum alone is ambiguous — enum 68 is shared with the
  M30 Dock — so the dialect is tracked per model and propagated from the selected
  drone into the mission config.
- WPML generator now emits the consumer dialect for Mini drones: `www.uav.com`
  namespace, minimal `template.kml`, no `payloadInfo`/`takeOffSecurityHeight`,
  and heights relative to the take-off point. Enterprise output is unchanged.
- KMZ generator places consumer-dialect files inside the `wpmz/` directory
  required by DJI Fly. Enterprise layout is unchanged.
- KMZ import detects the dialect from the WPML namespace so import → export
  round-trips stay in the same dialect.
- Marked the existing Mini 4 Pro as a consumer-dialect drone.
- Updated README, GUIDE, SPEC, and the mission-settings spec.
